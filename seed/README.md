# Демонстрационный слепок данных

`demo.dump` — состояние базы рабочего стенда на 2026-08-05, в формате
`pg_dump -Fc`. Нужен, чтобы новое развертывание сразу показывало заполненный
дашборд, а не пустые экраны в ожидании первого планового сбора.

Разворачивается одной командой:

```bash
bash scripts/seed-restore.sh
```

## Что внутри

| | |
|---|---|
| Сценарии | 133 |
| Снимки рынка | 4707 |
| Расчеты | 4715 |
| Предложения | 17 225 |
| Период наблюдений | 2026-08-03 .. 2026-08-05 |
| Размер | 12 МБ |

## Чего внутри нет и почему

**Предложения — только по последнему снимку каждого сценария.** Полная история
наблюдений — 564 тысячи строк и 1.2 ГБ, в репозиторий такое не кладут. Срез
составляет 3 % от этого объема и покрывает все экраны, которые читают
предложения: переплату у агента, разброс цен и надбавки. Расчеты и снимки при
этом лежат целиком, поэтому динамика стоимости и сравнение направлений
показывают всю историю.

**Учетные записи.** Слепок публичный, а хеши паролей рабочего стенда —
нет. Пользователи создаются заново из `BOOTSTRAP_*_PASSWORD` вашего `.env`:
`seed-restore.sh` вызывает `bootstrap` сразу после восстановления.

**Аудит, сырые ответы источников и HTML-снимки.** События аудита содержат
адреса и user-agent, сырые ответы — выдачу Туту и РЖД целиком. Ни то, ни другое
не нужно для демонстрации и не должно лежать в открытом репозитории. Ссылки на
них у предложений обнулены.

**Кэш результатов.** Воспроизводится сам, срок жизни — 45 минут.

## Обновление слепка

Слепок собирается из рабочего стенда и в этот момент читает базу, ничего в ней
не меняя: сборка идет через временную базу `tco_seed`, которая удаляется
следом. Порядок описан в [RUNBOOK](../docs/RUNBOOK.md).

Учтите, что каждое обновление добавляет в историю git еще один двоичный файл на
десяток мегабайт — обновляйте по необходимости, а не по расписанию.
