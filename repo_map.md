# Карта репозитория

Где что лежит и зачем. Составлено 7 августа 2026 года.

Платформа наблюдает рынок поездок по пяти городам и показывает витрину «Куда
поехать». Главное архитектурное решение, из которого следует всё остальное:
**наблюдение и расчёт разделены**. Снимок рынка фиксирует предложения как есть,
методика применяется к нему отдельно, результат неизменяем. Отсюда возможность
объяснить любую цифру до конкретного предложения и пересчитать историю новыми
правилами.

---

## Быстрая навигация: «мне надо поправить…»

| Задача | Куда идти |
|---|---|
| Источник изменил формат ответа | `tco/connectors/tutu_mcp.py`, `rzd.py` |
| Предложение неверно распознано | `tco/normalization/` |
| Не то попало в выборку / не то отброшено | `tco/engine/selection.py` |
| Медиана считается не так | `tco/engine/aggregation.py`, `statistics.py` |
| Пороги методики | `catalog/profiles/*.yaml` — **не код** |
| Что и когда собирается | `tco/services/observation_grid.py`, `tco/tasks/celery_app.py` |
| Витрина показывает не то | `tco/services/showcase.py`, `frontend/src/pages/ShowcasePage.tsx` |
| Сбор встал ночью | `tco/services/snapshot_builder.py`, `tco/tasks/`, `docker-compose.yml` |
| Новый экран | `frontend/src/pages/`, `tco/api/routers/` |

## Слои

```
источники → коннекторы → нормализация → снимок → отбор → агрегация → расчёт → API → интерфейс
             tco/connectors  tco/normalization  tco/db   tco/engine        tco/api  frontend
                          ↑                      ↑                    ↑
                 контракт коннектора      неизменяем        методика из профиля
```

Правило, которое держит всю конструкцию: **коннектор ничего не знает про
методику**, а движок — про источники. Между ними контракт
(`tco/connectors/contracts.py`), и всё неизвестное складывается в
`source_payload`, а не течёт дальше.

### `normalization/` — приведение к общей модели (1 000)

`normalizer.py` превращает ответ источника в `Offer`: выравнивает базы цен
(за пассажира / за всех / за период), считает отпечаток и ключ эквивалентности,
проставляет статус пригодности. `classify.py` — распознавание багажа,
возвратности, класса вагона, питания.

**Здесь решается, сопоставимо ли предложение со сценарием.** Ошибка на этом
слое не видна нигде дальше.

## Договорённости, которые не видны из структуры

1. **Снимок и расчёт неизменяемы.** Новая методика не переписывает историю — она
   создаёт новые расчёты.
2. **Пороги живут в профиле, а не в коде.** Активная версия профиля неизменяема:
   правка это новая версия.
3. **Предложение никогда не удаляется отбором** — только помечается причиной.
   На этом стоят и объяснимость, и пересчёт «что если».
4. **Отказ от обращения к источнику обязан оставлять запись**, иначе он
   превращается в утверждение о рынке.
5. **Комментарий объясняет «почему», а не «что».** Почти каждый в этом
   репозитории описывает дефект, который однажды случился.
6. **Данные лежат вне каталога исходников** (`${DATA_ROOT}`), и
   `docker compose down -v` на стенде не выполняется никогда: наблюдения
   невосполнимы, источники не отдают историю цен.
