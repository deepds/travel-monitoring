# Ограничения платформы

Документ фиксирует, что система **не** делает, и как правильно читать её
результат. Он обязателен к прочтению перед любым управленческим выводом,
опирающимся на показатель.

---

## 1. Что означает показатель

> **Расчетная типовая стоимость путешествия** — воспроизводимая оценка
> стоимости заданного сценария на основе доступных рыночных предложений,
> выбранного профиля расчета и активной версии методики.

Чем показатель **не** является:

| Не является | Почему |
|---|---|
| Офертой | Система не бронирует и не фиксирует цену; предложение может исчезнуть в момент обращения |
| Средним чеком | Нет данных о фактических транзакциях туристов |
| Фактической стоимостью поездки | Учитываются только транспорт и проживание |
| Прогнозом | Прогнозирование вне рамок MVP (Этап 3) |
| Медианой всех комбинаций | Итог — сумма компонентных медиан, а не медиана произведения множеств |

Последний пункт существенен: `total = median(транспорт) + median(проживание)`.
Такой комбинации предложений на рынке может не существовать. Показатель
отвечает на вопрос «сколько типично стоит поездка», а не «какую конкретную
пару билета и отеля можно купить».

---

## 2. Что не входит в стоимость

- Развлечения, экскурсии, музеи.
- Питание вне объекта размещения.
- Трансферы, такси, городской транспорт, аренда автомобиля.
- Визы, страховки, багажные сборы сверх включенных в тариф.
- Локальные расходы любого рода.

---

## 3. Ограничения модели поездки

| Ограничение | Пояснение |
|---|---|
| Нет комбинированных маршрутов | «Туда самолетом, обратно поездом» не поддерживается: авиа и ЖД — альтернативные варианты сценария |
| Нет оптимизации расписания | Система не подбирает удобные стыковки и не согласует время заселения с прибытием |
| Нет анализа стыковок | Пересадки сохраняются как атрибут, но их качество не оценивается |
| Один номер на весь состав | Размещение считается по одному подходящему номеру; вариант «два номера» вне MVP |
| Поддерживаемые классы ЖД — только плацкарт и купе | СВ, люкс и сидячие вагоны не агрегируются |
| Детский ЖД-тариф не моделируется | Коэффициент `rail_child_fare_ratio` по умолчанию 1.0: цена места умножается на общее число туристов. Реальные детские тарифы РЖД ниже, поэтому ЖД-компонент для семейных сценариев **завышен**. Значение конфигурируется в профиле |
| Конвертация валют не выполняется | Предложение в валюте, отличной от базовой, отбраковывается со статусом `INVALID_CURRENCY` |

---

## 4. Ограничения географии

- Поддерживаются 6 городов: Москва, Санкт-Петербург, Краснодар, Сочи,
  Калининград, Южно-Сахалинск.
- **Южно-Сахалинск** не имеет железнодорожной связи с материковой сетью:
  ЖД-сценарии для него отклоняются валидацией by design.
- **Калининград** формально имеет ЖД-сообщение, но оно идет транзитом через
  территорию других государств и требует отдельных документов. Направление
  поддерживается технически; практическая применимость ЖД-оценки для
  эксклава ограничена.
- Полный декартов набор маршрутов не создается: наблюдение ведется по
  управляемому каталогу приоритетных направлений.

## 5. Ограничения источников

| Ограничение | Следствие |
|---|---|
| Историю цен источники не отдают | История платформы начинается с даты начала наблюдений; ретроспективу восстановить невозможно |
| Часть источников требует партнерства | Яндекс Путешествия и TravelLine работают только при наличии учетных данных; без них контур проживания опирается на один источник |
| Источники могут меняться и отключаться | Схема ответа может измениться без предупреждения; коннектор в этом случае возвращает `SCHEMA_ERROR`, а не молчаливо пустой результат |
| Доступный горизонт зависит от активных источников | Он определяется не строгим пересечением всех источников, а наличием минимально достаточного покрытия |
| Два источника дают статистически слабый межисточниковый агрегат | При двух источниках итог — среднее двух медиан; устойчивость такой оценки ограничена |
| Один источник — режим `COMPLETE_SINGLE_SOURCE` | Quality Score снижается, в интерфейсе показывается предупреждение |

Актуальный статус каждого источника — в
[отчете о квалификации](SOURCE_QUALIFICATION.md).

## 6. Ограничения методики

- **Стартовые пороги не откалиброваны на реальных данных.** Значения
  `min_valid_offers = 5`, `max_data_age_minutes = 60`,
  `max_invalid_offer_ratio = 0.30`, `max_unclassified_fare_ratio = 0.40`,
  порог `PARTIAL_SUCCESS = 60` заданы методикой как стартовые и подлежат
  калибровке на challenge set после накопления наблюдений.
- **Веса Quality Score — экспертная оценка**, а не результат обучения.
- **Выбросы ищутся по IQR в пределах источника.** Правило конфигурируемо;
  выбор `PER_SOURCE` по умолчанию обусловлен тем, что агрегация тоже
  начинается с источника.
- **Неклассифицированный багаж никогда не попадает** в тарифы
  `CABIN_BAGGAGE` и `CHECKED_BAGGAGE`. Это сознательно сокращает выборку:
  лучше меньше предложений, чем ложная классификация.
- **Сопоставление объектов размещения между источниками приблизительно.**
  Ключ строится из нормализованного названия и фрагмента адреса; точное
  сопоставление требует геокодирования, которое вне рамок MVP. Поэтому
  межисточниковые группы эквивалентности для отелей менее надежны, чем для
  транспорта, где есть номер рейса или поезда.
- **`PARTIAL_SUCCESS` учитывается в KPI только при Quality Score выше порога.**

## 7. Ограничения истории и сравнимости

- История ограничена датой начала наблюдений; до накопления достаточного
  числа точек динамика малоинформативна.
- Изменение за 7 и 30 дней считается **по одному и тому же множеству
  сценариев**: иначе показатель отражал бы смену состава каталога, а не
  движение рынка. Число сопоставимых сценариев выводится рядом со значением.
- Сценарии заданы абсолютными датами и автоматически деактивируются после
  окончания поездки. Rolling-сценарии («всегда +30 дней») остаются в P1,
  поэтому длинные ряды по фиксированному горизонту бронирования в MVP
  не строятся.
- Исторические `ScenarioRun` не пересчитываются при смене версии профиля,
  движка или нормализации. Сравнение методик выполняется пересчетом снимка,
  а не подменой истории.

## 8. Ограничения синтетического источника

Песочница (`sandbox_alpha`, `sandbox_beta`) существует для прогона конвейера
без внешней сети: приемочные тесты, демонстрация, отладка методики.

- Данные **детерминированы и вымышлены**; рыночной информацией не являются.
- Любой результат с их участием помечается `contains_synthetic_data` —
  признак поднимается в снимок, расчет, объяснение, интерфейс и экспорт.
- Профиль `baseline` синтетические источники **не допускает**; они доступны
  только профилю `sandbox`.
- В продуктивной среде источники выключены (`SANDBOX_SOURCES_ENABLED=false`).

Результат, рассчитанный по профилю `sandbox`, не может использоваться для
управленческих выводов.

---

## 9. Ограничения инфраструктуры MVP

- Одна виртуальная машина, без горизонтального масштабирования и Kubernetes.
- Нет очереди с гарантией доставки уровня Kafka; Redis используется как
  брокер Celery.
- Внешний высоконагруженный API не предусмотрен: `/api/v1` рассчитан на
  внутренних потребителей.
- Полноценная система IAM отсутствует, если недоступен корпоративный SSO.
  Режим `DEPLOYMENT_MODE=OPEN` (без авторизации) допустим только временно и
  явно отражается в `/api/v1/version` и в интерфейсе.

## 10. Как читать результат правильно

| Что видите | Как трактовать |
|---|---|
| `SUCCESS`, уверенность `HIGH` | Оба компонента рассчитаны по нескольким источникам с низким расхождением — оценка пригодна для сравнения направлений |
| `SUCCESS`, уверенность `MEDIUM` | Оценка пригодна, но один из компонентов опирается на единственный источник либо качество ниже целевого |
| `PARTIAL_SUCCESS` | Один компонент отсутствует. Итоговая полная стоимость **не рассчитывается**, старое значение не подставляется. Сравнивать можно только имеющийся компонент |
| Уверенность `INSUFFICIENT` | Итог **запрещено** показывать как полноценную стоимость |
| `NO_DATA` | Пригодных предложений не получено — это факт о доступности данных, а не о рынке |
| `UNSUPPORTED` | Сценарий отклонен валидацией; внешние запросы не выполнялись |
| Широкий диапазон P25–P75 | Рынок неоднороден; медиана хуже описывает выборку |
| Высокое межисточниковое расхождение | Источники видят разный инвентарь; вывод требует ручной проверки |

Любой вывод, чувствительный к абсолютной величине, следует подтверждать
ручной проверкой на сайтах источников — процедура описана в
[challenge set](CHALLENGE_SET_RESULTS.md).
