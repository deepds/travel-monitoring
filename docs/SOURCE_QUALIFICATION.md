# Отчет о квалификации источников

Результат Source Qualification Spike (SCOPE-R E §1). Документ фиксирует, что
именно было проверено фактически, а что осталось непроверенным и почему.

**Дата проверки:** 2026-08-03 / 2026-08-04
**Стенд проверки:** узел `nemo` (192.168.10.67), прямой выход в интернет

> Перечень API из исходного исследования рассматривался как список
> кандидатов, а не подтвержденных интеграций. Решение по каждому источнику —
> `APPROVED` / `CONDITIONAL` / `CANDIDATE` / `REJECTED`.

**Итог по KPI покрытия:**

- Транспортный контур: **2 пригодных источника** (Туту, РЖД) — требование

- Контур проживания: **1 подтвержденный источник** (Туту). Второй источник

## 2. Туту.ру (MCP) — `APPROVED`

| Критерий | Результат |
|---|---|
| Реальная доступность | Подтверждена: `initialize` + `tools/list` отвечают |
| Задержка | 2348 мс на установление сессии и список инструментов |
| Авторизация | Не требуется, публичный эндпоинт `https://mcp.tutu.ru/mcp` |
| Протокол | MCP поверх Streamable HTTP (JSON-RPC), поддержан ответ и в SSE |
| Доступные инструменты | 16, включая `search_avia`, `search_rail`, `search_hotels`, `get_offer_details`, `create_checkout_link` |
| Покрытие городов | Все 8 городов каталога |
| Произвольные даты | Поддерживаются |
| Число пассажиров | `adults` / `children` / `infants` |
| Round-trip | Поддерживается для авиа; для ЖД коннектор собирает из двух односторонних поисков |
| Багаж | Строкой в `price.baggage` — классифицируется нормализацией |
| Пересадки | Сохраняются посегментно |
| Классы ЖД | `car_type` (КУПЕ / ПЛАЦ / СВ / СИДЯЧИЙ) |
| Тип размещения, звездность, питание, отмена | Присутствуют в выдаче отелей |
| Квоты | **Не документированы** |
| Право хранения | Ограничений на хранение ответов не заявлено |
| Историчность | Отсутствует: только будущие даты |

**Особенность, повлиявшая на реализацию.** Точные имена аргументов
инструментов публично не зафиксированы. Коннектор читает `tools/list` и
сопоставляет логические поля запроса с фактической схемой по списку
кандидатов. При переименовании параметра источник вернет `SCHEMA_ERROR` с
перечнем доступных аргументов, а не молчаливый пустой результат.

**Ограничение темпа.** Лимиты не опубликованы, поэтому задано
самоограничение **60 запросов/мин**: часовая пачка планового сбора
укладывается примерно в 13 минут.

**Вывод.** Опорный источник MVP: единственный, кто покрывает все три
вертикали без авторизации.

## 3. РЖД (ticket.rzd.ru) — `APPROVED`

| Критерий | Результат |
|---|---|
| Реальная доступность | Подтверждена с узла `nemo`: `HTTP 200`, connect 10 мс, TLS 60 мс |
| Пример ответа | `/api/v1/suggests?Query=Москва` → `expressCode: 2000000`, `nodeType: city` |
| Авторизация | Не требуется |
| Протокол | REST JSON; поиск цен использует двухфазный протокол `RID` |
| Покрытие городов | Все города каталога, кроме Южно-Сахалинска и Геленджика (нет ЖД) |
| Классы вагонов | Купе и плацкарт различаются и агрегируются раздельно |
| Квоты | **Не документированы** |
| Историчность | Отсутствует |

### 3.1. Два подтвержденных ограничения доступа

**Фильтрация по User-Agent.** Сервис отвечает `403 Forbidden` на запросы с
пользовательским агентом по умолчанию у консольных клиентов (`curl/*`), но
принимает запросы с осмысленным идентифицирующим `User-Agent`. Коннектор
представляется собственным агентом с контактом — это добросовестная
идентификация клиента, а не обход защиты. Проверено: тот же URL с нашим
агентом возвращает `200`.

**Сетевая доступность.** С рабочей машины разработчика за корпоративным VPN
TCP-соединение с `ticket.rzd.ru` не устанавливается: DNS резолвится, но
connect не завершается. С узла `nemo` без VPN источник доступен. Отсюда
эксплуатационное требование: **узел сбора должен иметь прямой выход в
интернет**, иначе ЖД-контур деградирует до одного источника.

**Ограничение темпа:** **30 запросов/мин** — занижено сознательно ввиду
антибот-защиты. Часовая пачка проходит примерно за 2 минуты.

**Вывод.** Пригоден. Дает детализацию по типам вагонов и минимальным ценам,
которой нет у агрегатора.

## 4. Яндекс Путешествия — `CONDITIONAL`

| Критерий | Результат |
|---|---|
| Документация | Изучена: `hotels/suggest`, `hotels/search`, `hotels/hotel`, отзывы, изображения |
| Авторизация | OAuth-токен партнера Яндекс Дистрибуции — **отсутствует** |
| Проверка вживую | **Не выполнена**: без токена любой запрос вернет 401 |
| Качество полей | По документации — богатое: конфигурации кроватей, правила отмены с периодами, питание кодами RO/BB/HB/FB/AI, рейтинги |
| Особенности | Пагинация через `page_token`, часть ответов требует polling (`complete: false`) |

**Статус реализации.** Коннектор написан по документации и включается
автоматически при заданном `YANDEX_TRAVEL_TOKEN`. Без токена источник
сообщает `DISABLED / NOT_CONFIGURED` — это штатное состояние, а не ошибка.

**Что требуется для перевода в `APPROVED`:** получить партнерский токен,
выполнить `POST /api/v1/sources/{id}/health-check`, прогнать challenge set с
профилем `baseline` и сверить не менее пяти сценариев вручную.

**Почему это важно.** Это наиболее реалистичный кандидат на **второй
источник проживания**, без которого KPI покрытия остается невыполненным.

## 5. TravelLine — `CANDIDATE`

| Критерий | Результат |
|---|---|
| Документация | Изучена: Content, Search, PMS, CancellationRules, Reviews |
| Авторизация | OAuth2 `client_credentials`, токен живет 15 минут — **ключей нет** |
| Проверка вживую | **Не выполнена** |
| Документированные лимиты | 50/сек, 200/мин, 3000/час для стандартных методов |
| Глубина данных | Максимальная среди рассмотренных: правила отмены с периодами штрафов, отзывы по категориям |

**Честная оговорка.** Точная форма тела `POST /v1/search` и имена полей
ответа в публичной документации не зафиксированы. Поэтому маппинг ответа
вынесен в конфигурацию источника (`config.response_paths`) со значениями по
умолчанию из документации. **Перевод в `APPROVED` возможен только после
прогона с реальными ключами и сверки маппинга** — иначе коннектор вернет
пустую выдачу при формально успешном запросе.

## 6. Skyscanner — `REJECTED` для MVP

| Критерий | Результат |
|---|---|
| Поезда | Не поддерживает — а ЖД является одним из двух видов транспорта MVP |
| Авиа | Сильнейший источник: 52 рынка, 1300+ поставщиков |
| Авторизация | API-ключ по партнерской заявке — отсутствует |
| Протокол | create / poll с временем жизни сессии ~1 час |

**Обоснование отказа.** Не закрывает ЖД, пересекается с Туту по авиа и
отелям, требует партнерства. Для MVP ценности не добавляет. Кандидат на
Этап 2 при выходе за пределы России.

## 7. Синтетические источники — `APPROVED` только для тестов

Песочницы «Альфа» и «Бета» — детерминированный генератор рынка. Существуют
для прогона конвейера без внешней сети: приемочные тесты, демонстрация,
отладка методики.

Защита от подмены рыночных данных:

- источники помечены `is_synthetic`, признак поднимается в снимок, расчет,
  объяснение, интерфейс и экспорт (`contains_synthetic_data`);
- профиль `baseline` их **не допускает** — только профиль `sandbox`;
- в продуктивной конфигурации выключены (`SANDBOX_SOURCES_ENABLED=false`).

## 8. Открытые пункты

| Пункт | Влияние | Что требуется |
|---|---|---|
| Второй источник проживания не подтвержден | KPI покрытия SCOPE-R O §2 не выполнен; проживание считается по одному источнику, режим `COMPLETE_SINGLE_SOURCE`, Quality Score снижен | Партнерский токен Яндекс Путешествий либо ключи TravelLine |
| Лимиты Туту и РЖД неизвестны | Риск получить 429 или блокировку по IP при росте частоты | Наблюдать `error_breakdown` на экране качества; при появлении 429 снизить `rate_limit_per_minute` |
| Маппинг ответа TravelLine не сверен | Возможна пустая выдача при успешном запросе | Прогон с реальными ключами |
| Юридические условия автоматического доступа | Не получено письменного подтверждения ни от одного источника | Запрос через юридическую службу до промышленной эксплуатации |
| Узел сбора требует прямого интернета | За VPN ЖД-контур недоступен | Зафиксировано в требованиях к развертыванию |

## 9. Регламент повторной квалификации

- Health check всех включенных источников — ежечасно.
- Source Confidence — ежедневно за окно 30 дней.
- Технический горизонт бронирования — ежедневно.
- Полная переквалификация — при смене схемы ответа (`SCHEMA_ERROR`), при
  падении успешности ниже 90% за сутки или при изменении условий доступа.

Перевод источника в `APPROVED` выполняется **явным решением
администратора**: автоматическая квалификация исказила бы смысл go/no-go.
